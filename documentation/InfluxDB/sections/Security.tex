\section{Security}
\label{sec:security}

\subsection{Posture}
The historian operates on a university research lab LAN and is not exposed to the public internet. The security design is therefore pragmatic and aligned with the phased approach documented in the companion MQTT design document. This section describes historian-side measures only; broker-side authentication, ACLs, and TLS are covered in the MQTT design document.

\subsection{InfluxDB Access Control}
InfluxDB v2 uses token-based authentication for all API access. As built, a single admin token, set on first start from \texttt{INFLUXDB\_TOKEN} in the \texttt{.env} file, is used by Telegraf and \texttt{daq2-ingest} to write and by Grafana to read. \texttt{daq2-ingest} also uses it to create the \texttt{waveform} and \texttt{waveform\_1s} buckets on first start.

\paragraph{Deferred} The design specified scoped tokens, so that a compromised token has a limited blast radius:
\begin{table}[H]
\centering
\caption{Planned InfluxDB API Tokens}
\begin{tabular}{lll}
\hline
\textbf{Token} & \textbf{Scope} & \textbf{Used by} \\
\hline
Telegraf write token & Write-only to \texttt{telemetry} bucket & Telegraf bridge \\
Ingest write token   & Write-only to \texttt{waveform} and \texttt{waveform\_1s} & \texttt{daq2-ingest} \\
Grafana read token   & Read-only on all three buckets  & Grafana data source \\
Admin token          & Full organisation access               & Local admin / ad-hoc Flux queries \\
\hline
\end{tabular}
\end{table}

With scoped tokens, the buckets would be created in advance rather than by \texttt{daq2-ingest}. Tokens are stored as environment variables and injected at runtime: into the Telegraf configuration via \texttt{\$\{INFLUXDB\_TOKEN\}}, and into \texttt{daq2-ingest} and the Grafana data source through their container environments. They are never written to configuration files or committed to version control.

\subsection{Network Binding}
The InfluxDB HTTP API is published only on the host's loopback interface by the Docker port mapping (\texttt{127.0.0.1:8086:8086}), so it is not reachable from the lab LAN directly. Telegraf, \texttt{daq2-ingest}, and Grafana reach it over the internal Docker network by container name. Administrators access the InfluxDB UI through an SSH tunnel to the historian server.

\subsection{Grafana Authentication}
Grafana is published on all interfaces (port 3000) so that dashboards can be viewed from the lab LAN. Anonymous access is disabled, and the \texttt{admin} password is set on first start from \path{GRAFANA_ADMIN_PASSWORD}.

\paragraph{Deferred} A separate read-only \texttt{viewer} account for demonstrations was designed but not provisioned.

\subsection{Future Hardening}
Consistent with the MQTT design's phased security model, the following measures are deferred:
