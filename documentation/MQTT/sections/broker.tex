\section{Broker Selection \& Configuration}

Eclipse Mosquitto 2 is selected as the MQTT broker. This is suitable for a research testbed with two DAQ nodes as it is:
\begin{itemize}[noitemsep]
  \item lightweight
  \item well documented
  \item suitable for co-deployment on the historian server alongside InfluxDB without significant resource contention
  \item carries no licensing constraints under the Eclipse Public Licence
\end{itemize}
Alternatives such as EMQX and HiveMQ were considered but are designed for large-scale deployments with thousands of concurrent clients; the additional operational complexity is not justified at this scale.

The broker runs as the \texttt{eclipse-mosquitto:2} Docker container on the historian server (see the InfluxDB design document for the full Docker Compose deployment). The as-built configuration (\path{mosquitto/config/mosquitto.conf}) is:

\begin{lstlisting}[language=toml]
listener 1883
allow_anonymous true
persistence true
persistence_location /mosquitto/data/
log_dest file /mosquitto/log/mosquitto.log
log_dest stdout
\end{lstlisting}

Port 1883 is used for lab LAN traffic. Network exposure is controlled by the Docker port mapping rather than the listener address: the default mapping \texttt{127.0.0.1:1883:1883} admits only clients on the server itself (such as a test message published with \texttt{mosquitto\_pub}), and must be changed to \texttt{1883:1883} before DAQ nodes can connect. Anonymous connections are currently permitted; see Section~\ref{sec:security}. Persistence is enabled, although with all telemetry published at QoS~0 there are no queued messages for it to preserve.

\paragraph{Deferred} The originally designed authentication (\texttt{password\_file}), explicit LAN interface binding, and \texttt{max\_inflight\_messages}/\texttt{max\_queued\_messages} limits were not applied. TLS on port 8883 remains a future hardening measure.
